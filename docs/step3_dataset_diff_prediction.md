# 📘 step3_dataset_diff_prediction 教学文档：

# 差分预测数据集构造——让模型学习"温度怎么变"，而非"温度是多少"

## 一、这个文件是做什么的？

经过 Step 2，我们已经知道"哪些传感器是领先指标"。但直接把原始数据扔进神经网络，模型会面临两个致命难题：

1. **基线漂移**：碳化取出液温度可能长期稳定在 40°C，也可能因季节/批次原因稳定在 24°C。模型要花大量神经元去"记住当前基线是多少"，而不是学习"温度为什么会波动"。
2. **量纲混乱**：压力是 MPa，流量是 m³/h，温度是 °C，阀门开度是 0~100%。如果不统一尺度，模型会被大数值特征（如流量 5000）带偏，忽略小数值但重要的特征（如阀门 0.5）。

**这个脚本的目标就是：**

1. 给原始特征增加"速度"信息（1分钟变化、3分钟变化）
2. 按 Step 2 发现的领先时间，把特征平移对齐
3. 按时间顺序切分训练/验证/Demo 三段（**绝不允许随机打乱！**）
4. 把所有特征缩放到同一尺度（标准化）
5. **核心创新**：不预测未来 30 分钟的绝对温度，而是预测"每分钟温度变化了多少"
6. 用滑动窗口把长序列切成"输入 30 分钟 → 预测未来 30 分钟"的样本对
7. 保存为高性能二进制格式

------

## 二、整体流程图（文字版）

```plain
读取 merged_wide_table.parquet
    ↓
add_momentum_features: 为每个特征增加 1阶差分、3阶差分（速度特征）
    ↓
apply_lag_shifts: 按 Step 3 的 JSON 配置，把领先特征向前平移对齐
    ↓
split_timeseries: 按时间硬切分 → 训练(14天) | 验证(2天) | Demo(剩余)
    ↓

    ↓
create_diff_sliding_windows: 
    对标准化后的数据，用 30分钟窗口滑动采样
    Y标签 = 未来30分钟的温度差分（不是绝对温度！）
    同时保存窗口最后一个绝对温度（用于还原）
    ↓
保存为 train/val/demo .npz
```

## 三、代码分段拆解 + 技术扩展

### 3.1 动量特征构造：`add_momentum_features`

```python
def add_momentum_features(df, target_var):
    features = [col for col in df.columns if col != target_var]
    for feat in features:
        df[f"{feat}_diff1"] = df[feat].diff(periods=1)
        df[f"{feat}_diff3"] = df[feat].diff(periods=3)
    return df
```

**是什么？** 为每个原始特征增加两列"速度"：

- `_diff1`：当前值 - 1分钟前的值（瞬时速度）
- `_diff3`：当前值 - 3分钟前的值（短期趋势）

**为什么需要？** 工业控制中，**"压力正在快速上升"** 比 **"压力当前是 2.5 MPa"** 更有预警价值。`diff1` 捕捉突变，`diff3` 平滑噪声后捕捉趋势。这相当于给模型提供了"一阶导数"信息。

#### 技术扩展：时序特征工程方法家族

| 特征类型                     | 构造方式                | 物理含义               | 优点                     | 缺点                    | 适用场景                                          |
| :--------------------------- | :---------------------- | :--------------------- | :----------------------- | :---------------------- | :------------------------------------------------ |
| **一阶差分 diff1（本方案）** | `x_t - x_{t-1}`         | 瞬时变化率             | 对基线漂移免疫，突出扰动 | 对高频噪声敏感          | **本方案选择**：工业传感器 1 分钟采样，噪声可控 |
| **高阶差分 diff(n)**         | `x_t - x_{t-n}`         | n分钟累积变化          | 平滑短期噪声，看趋势     | 滞后 n 分钟，丢失即时性 | 噪声极大、需要看长趋势的系统                      |
| **移动平均 MA(n)**           | `mean(x_{t-n+1}...x_t)` | 近期平均水平           | 降噪效果极好             | 滞后明显，丢失突变信息  | 流量、液位等缓慢变化量                            |
| **移动标准差 STD(n)**        | `std(x_{t-n+1}...x_t)`  | 近期波动幅度           | 捕捉"是否进入不稳定状态" | 单独使用无方向信息      | 精馏塔、反应器等需要监控稳定性的场景              |
| **指数加权移动平均 EMA**     | 加权平均（近期权重高）  | 近期趋势（比MA灵敏）   | 比 MA 更快响应变化       | 需调超参（衰减系数）    | 金融时序、需要快速跟踪趋势的场景                  |
| **小波分解**                 | 多尺度频域分解          | 分离高频噪声与低频趋势 | 数学严谨，去噪能力强     | 计算复杂，解释性差      | 信号处理、振动分析                                |

**为什么选择 diff1 + diff3 的组合？**

1. **diff1** 提供"此刻正在发生什么"的即时信号，帮助模型捕捉阀门动作、流量突变等快速事件。
2. **diff3** 提供"过去 3 分钟的趋势"的平滑信号，过滤掉单分钟采样抖动（如通信偶发延迟导致的尖刺）。
3. **不选 MA/EMA**：因为 MA/EMA 会引入"未来信息泄露"（计算 t 时刻的 MA 需要用到 t 时刻的值，但在滑动窗口里这是允许的；然而 MA 会让特征变得"迟钝"，而 diff 保留了变化的方向性）。
4. **计算极简**：`diff()` 是 pandas 内置的 O(n) 操作，不增加任何超参数负担。

> **注意**：`diff()` 会在数据头部产生 `NaN`（因为第 0 行没有前一行可减），后续 `dropna()` 或 `ffill()` 会处理。这是正常现象。

### 3.2 滞后平移：`apply_lag_shifts`

```python
def apply_lag_shifts(df, config_path, target_var):
    with open(config_path, 'r', encoding='utf-8') as f:
        feature_config = json.load(f)
    for feat, lag in feature_config.items():
        if feat == target_var: continue
        if lag > 0:
            df[feat] = df[feat].shift(lag)
```

**是什么？** 读取 Step 2 生成的 `feature_config.json`（如 `"取出液流量": 3`），然后把该特征列**向上平移 3 行**。

**为什么要平移？** Step 2 发现"取出液流量"提前 3 分钟预示取出液温度变化。如果不平移，模型在"当前时刻"看到的反应段温度，其实是**3 分钟后的未来信息**（数据泄露！）。`shift(3)` 把"3 分钟前的取出液流量"搬到"当前行"，让模型能用**历史信息**预测未来。

#### 技术扩展：时间对齐与数据泄露防护

| 技术                       | 原理                    | 防泄露能力         | 复杂度 | 适用场景                                       |
| :------------------------- | :---------------------- | :----------------- | :----- | :--------------------------------------------- |
| **`shift(lag)`（本方案）** | 固定平移领先特征        |  强（显式前移） |  极简 | **本方案选择**：单变量固定滞后，规则时间序列 |
| `merge_asof` + 时间窗      | 最近邻匹配后截断        |  强             |  中等 | 不规则时间戳、事件驱动数据                     |
| 时间序列交叉验证 TS-CV     | 严格按时间切分训练/验证 |  强             |  中等 | 任何时序模型调参的验证策略                     |
| 随机打乱 + 时序掩码        | 打乱后掩盖未来信息      |  中（易出错）    |  高   | 自监督预训练（如 BERT 式掩码语言模型）         |
| 不做处理                   | 直接用原始时间对齐      |  无（严重泄露）   | 零     | 仅限同步特征，且需人工确认无领先关系           |

**数据泄露（Data Leakage）是工业时序建模的头号杀手。** 一个经典的泄露案例：把"反应段温度"和"取出液温度"同时作为输入，不做平移。模型"学会"了"反应段温度一涨，取出液温度就涨"，但实战中反应段温度涨的时候，取出液温度**还没涨**（有 8 分钟滞后）。模型在训练集上表现完美，上线后完全失效。

`shift(lag)` 是最朴素、最可审计的防泄露手段——你可以打开 JSON 文件，逐行检查每个特征的平移分钟数，工艺人员也能看懂。

### 3.3 时间序列切分：`split_timeseries`

```python
def split_timeseries(df):
    train_end = 14 * 1440
    val_end = train_end + 2 * 1440
    return df.iloc[:train_end], df.iloc[train_end:val_end], df.iloc[val_end:]
```

**是什么？** 按**时间顺序**硬切分三段：

- 训练集：前 14 天（14 × 1440 分钟）
- 验证集：接下来 2 天
- Demo 集：剩余所有数据

**为什么必须按时间切分？为什么不能随机打乱？**

这是时序建模与表格建模（如鸢尾花分类）的**本质区别**：

| 切分方式                   | 原理                         | 问题                                 | 后果                                         |
| :------------------------- | :--------------------------- | :----------------------------------- | :------------------------------------------- |
| **时间顺序切分（本方案）** | 训练集 = 过去，验证集 = 未来 | 无                                   |  模拟真实部署：用过去数据训练，预测未来     |
| 随机打乱后切分             | 从全量数据中随机抽 80% 训练  | 训练集可能包含"未来数据"             |  模型偷看了未来，验证集指标虚高，上线后暴跌 |
| K-Fold 交叉验证            | 数据分成 K 份轮流验证        | 时序数据不满足 IID（独立同分布）假设 |  每折都混有过去和未来，验证无意义           |

**工业现场的数据分布会随时间漂移**（设备老化、季节变化、原料批次更换）。只有用"过去训练、未来验证"，才能真实评估模型在未来工况上的泛化能力。

#### 技术扩展：时序验证策略家族

| 策略                          | 切分方式                           | 优点                                           | 缺点                               | 适用场景                                            |
| :---------------------------- | :--------------------------------- | :--------------------------------------------- | :--------------------------------- | :-------------------------------------------------- |
| **硬切分 Hold-out（本方案）** | 固定比例按时间切                   | 简单、可复现、与部署一致                       | 验证集只有一次，方差大             | **本方案选择**：数据量足够（16天+），单次验证可信 |
| 滚动原点验证 Rolling Origin   | 训练集逐步增长，验证集向前滚动     | 模拟"持续学习"场景，评估模型随数据增长的稳定性 | 计算量大，需训练多次               | 在线学习系统、模型需要定期重训练                    |
| 滑动窗口验证 Walk-forward     | 固定长度训练窗，验证窗紧随其后滑动 | 严格模拟部署时的窗口长度                       | 早期数据被浪费，超参敏感           | 高频交易、需要固定记忆长度的场景                    |
| 阻塞交叉验证 Blocked CV       | 将数据分块，块内打乱、块间保持时序 | 减少验证方差，同时防泄露                       | 块大小难调，块边界可能切在事件中间 | 中等数据量、需要多次验证取平均                      |

**为什么选择硬切分？** 本项目数据量约 30 天（43200 分钟），14 天训练 + 2 天验证 + 剩余 Demo 是工业项目的经典比例。硬切分的验证集是"固定的一段未来"，与最终 Demo 的评估逻辑完全一致，且只需训练一次模型，适合工程落地。

>  **关键细节**：`1440` 是一天的分钟数（24 × 60）。用分钟数硬编码而不是比例（如 `0.8`），是为了**确保切分点落在自然日边界**，避免把一天中间切两半，导致日周期性特征（如白班/夜班差异）在训练/验证间分布不均。

### 3.4 标准化：`normalize_and_save_params`

```python
def normalize_and_save_params(df_train, df_val, df_demo, features):
    means = df_train[features].mean()
    stds = df_train[features].std()
    stds[stds == 0] = 1e-6
    
    def scale(d): return (d[features] - means) / stds
    return scale(df_train), scale(df_val), scale(df_demo)
```

**是什么？** **Z-score 标准化**：对每个特征，减去训练集的均值，除以训练集的标准差。

**公式**：`x_norm = (x - μ) / σ`

**为什么必须做？** 神经网络对输入数值范围极其敏感。如果"流量"列是 0~5000，"阀门开度"是 0~100，模型会天然认为"流量更重要"（因为数值大），而实际上阀门 1% 的变化可能比流量 100m³ 的变化更关键。标准化让所有特征都缩放到**均值 0、标准差 1**的尺度，模型才能公平学习。

#### 技术扩展：标准化/归一化方法家族

| 方法                  | 公式                      | 对异常值敏感度                | 分布假设     | 优点                             | 缺点                              | 适用场景                                                     |                        |                       |
| :-------------------- | :------------------------ | :---------------------------- | :----------- | :------------------------------- | :-------------------------------- | :----------------------------------------------------------- | ---------------------- | --------------------- |
| **Z-score（本方案）** | `(x - μ) / σ`             |  高（μ和σ受异常值影响）      | 假设近似正态 | 保留异常值信息，有明确统计意义   | 异常值会拉偏 μ 和 σ               | **本方案选择**：工业数据经 Step 1 清洗后，极端异常已被剔除，近似正态 |                        |                       |
| Min-Max               | `(x - min) / (max - min)` |  极高（max/min受异常值决定） | 无           | 严格缩放到 [0,1]                 | 异常值直接毁掉整个尺度            | 图像像素（天然有界 0~255）、需要严格输出范围时               |                        |                       |
| RobustScaler          | `(x - median) / IQR`      |  极低                        | 无           | 用中位数和四分位距，抗异常值极强 | 对正常数据的压缩不如 Z-score 均匀 | 原始数据含大量未清洗异常值、传感器频繁跳变                   |                        |                       |
| MaxAbs                | `x / max(                 | x                             | )`           |  高                             | 无                                | 不移动中心，适合稀疏数据                                     | 对正负不对称数据效果差 | 文本 TF-IDF、稀疏矩阵 |
| QuantileTransformer   | 映射到均匀/正态分位数     |  极低                        | 强制转换     | 把任意分布变成正态或均匀         | 计算慢，可解释性丧失              | 特征分布极度偏斜（如长尾分布）、竞赛刷分                     |                        |                       |
| 不做标准化            | 原始值直接输入            | —                             | —            | 零计算成本                       | 模型几乎无法收敛，或收敛极慢      |  几乎从不适用（除非所有特征已同量纲同量级）                 |                        |                       |

**为什么选择 Z-score？**

1. **工业数据经清洗后接近正态**：Step 1 已经剔除了质量戳和明显异常值，稳态工况下的温度/压力/流量近似服从正态分布。
2. **与差分预测天然兼容**：差分后的序列均值近似为 0，Z-score 标准化后尺度统一，且不会破坏"差分 ≈ 0"的物理直觉。
3. **可逆性清晰**：还原公式 `x = x_norm × σ + μ`，工艺人员能理解每一步在做什么。
4. **LSTM 的偏好**：LSTM 使用 tanh 激活函数，输入在 [-3, 3] 附近时梯度最健康。Z-score 后约 99.7% 的数据落在 [-3, 3]，是 LSTM 的"舒适区"。

>  **关键铁律**：`means` 和 `stds` **必须只用训练集计算**，然后 applied 到验证集和 Demo 集。如果用全量数据算均值，验证集信息就"泄露"到训练标准化参数里了。

>  **防除零**：`stds[stds == 0] = 1e-6`。如果某个特征在训练集里完全不变（如某阀门始终 100%），标准差为 0，除零会导致 `Inf`。用极小值替代，相当于"该特征标准化后始终为 0"，模型会自动学会忽略它。

### 3.5 核心：差分滑动窗口 `create_diff_sliding_windows`

这是整个 Step 3 乃至全项目的**灵魂函数**。我们逐行拆解。

#### 3.5.1 滑动窗口切分

Python

复制

```python
for i in range(0, len(df) - input_len - output_len + 1, stride):
    x_win = data_X[i: i + input_len]
```

**是什么？** 用一个长度为 30 的窗口，在数据上**以步长 5 滑动**，每次截取一段作为模型输入。

**可视化：**

plain

复制

```plain
时间轴: [0][1][2][3][4][5][6][7] ... [29][30][31] ... [59]
         └────── input_len=30 ──────┘
                                    └────── output_len=30 ──────┘
         
stride=5: 下一次窗口从 i=5 开始
         [5][6]...[34][35]
```

**为什么 stride=5 而不是 1？**

- `stride=1`：相邻样本高度重叠，训练集膨胀 5 倍，但信息增量极小，模型过拟合风险高，训练速度慢。
- `stride=5`：每 5 分钟取一个样本，既覆盖了主要变化模式，又避免了冗余。工业现场模型每 5 分钟推理一次，与训练时的采样逻辑一致。

#### 技术扩展：滑动窗口策略家族

表格





| 策略                                      | 步长 vs 窗长                  | 样本重叠度                   | 优点                       | 缺点                           | 适用场景                                                   |
| :---------------------------------------- | :---------------------------- | :--------------------------- | :------------------------- | :----------------------------- | :--------------------------------------------------------- |
| **有重叠滑动（本方案，stride < window）** | stride=5, window=30           | 高（相邻样本共享25个时间点） | 数据利用率高，覆盖细微变化 | 样本相关性强，需防过拟合       | **本方案选择**：数据量中等（14天），需要充分学习波动模式 |
| 无重叠滑动（stride = window）             | stride=30, window=30          | 零重叠                       | 样本完全独立，验证更可靠   | 数据利用率低，可能漏掉关键事件 | 数据量极大、或事件稀疏                                     |
| 膨胀窗口 Expanding Window                 | window 从 1 增长到 N          | 早期样本短，后期样本长       | 模拟"记忆逐渐积累"         | 早期样本不稳定，工程复杂       | 需要显式建模"看的历史越长越准"的系统                       |
| 多尺度窗口                                | 同时使用 10min/30min/60min 窗 | 多尺度并行                   | 捕捉短/中/长期模式         | 特征维度爆炸，计算成本高       | 金融高频交易、多周期耦合系统                               |

#### 3.5.2 差分标签构造（核心创新）

Python

复制

```python
y_abs = data_Y_absolute[i + input_len: i + input_len + output_len]
last_known_abs = data_Y_absolute[i + input_len - 1]
y_abs_with_last = np.vstack([last_known_abs, y_abs])
y_diff = np.diff(y_abs_with_last, axis=0)
```

**是什么？** 不预测 `[y_1, y_2, ..., y_30]`（绝对温度），而是预测 `[Δy_1, Δy_2, ..., Δy_30]`，其中 `Δy_t = y_t - y_{t-1}`。

**为什么这是神来之笔？**

想象你要教一个实习生预测明天的股价：

- **方案 A（绝对预测）**："明天股价是 150 元。" 实习生必须先记住"最近股价在 145~155 区间波动"这个基线，然后再学"为什么会波动"。
- **方案 B（差分预测）**："明天股价比今天涨 2 元。" 实习生不需要关心当前股价是 150 还是 15，只需要学习"驱动变化的因素"。

**工业场景下，基线漂移是常态**（不同批次、不同季节），但**物理规律是恒定的**（冷却水多开 5%，温度下降 0.3°C）。差分预测让模型**剥离基线，专注学习物理响应**。

#### 技术扩展：时序预测目标设计家族

表格





| 目标类型                  | 预测对象                   | 对基线漂移的鲁棒性 | 对突变预测的灵敏度      | 还原复杂度           | 适用场景                                     |
| :------------------------ | :------------------------- | :----------------- | :---------------------- | :------------------- | :------------------------------------------- |
| **差分预测 Δy（本方案）** | `y_t - y_{t-1}`            |  极强           |  高                  | 需 cumsum 累加还原   | **本方案选择**：大惯性系统、基线漂移频繁   |
| 残差预测 Residual         | `y_t - y_{last_known}`     |  极强           |  中（只关注终点偏差） | 简单加法还原         | 只需要预测"终点偏离多少"，不关心中间路径     |
| 绝对预测 Absolute         | `y_t`                      |  弱               |  低（被基线淹没）      | 无需还原             | 基线极稳定、或模型容量极大（如 Transformer） |
| 趋势+基线分解             | 分别预测 trend 和 seasonal |  强              |  中                   | 需分解+合成          | 有明显周期性的系统（如电力负荷、季节性温度） |
| 分位数预测 Quantile       | `P(y_t < q)`               |  强              |  高                  | 需多模型或分位数回归 | 需要预测区间而非点值（如风险管理）           |

**为什么选择差分而非残差？**

- 残差预测只关心"30 分钟后比此刻高多少"，不关心中间每分钟怎么变。而工业 DCS 需要**连续的预测曲线**来显示趋势。
- 差分预测输出 30 个连续差分值，还原后是 30 个连续绝对温度值，可以画出平滑的趋势线。
- 差分对**长程误差累积有暴露作用**：如果模型连续 30 分钟都预测"涨 0.1°C"，cumsum 后会变成涨 3°C，这种系统性偏差在评估时会被 RMSE 放大，倒逼模型学习更精细的波动模式。

>  **还原公式**（Step 5 使用）：
>
> plain
>
> 复制
>
> ```plain
> 真实温度序列 = last_known_abs + cumsum([Δy_1, Δy_2, ..., Δy_30])
> ```
>
> 
>
> `last_known_abs` 是输入窗口的最后一个真实温度，作为"锚点"。差分预测只负责"从锚点出发怎么变"，不负责"锚点本身是多少"。

#### 3.5.3 保存基准点：`Y_last_abs_list`

Python

复制

```python
Y_last_abs_list.append(last_known_abs)
```

**为什么必须保存？** 因为模型输出的是**标准化后的差分**。还原时：

1. 反标准化差分：`Δy_real = Δy_norm × target_std`
2. 反标准化锚点：`y_last_real = y_last_norm × target_std + target_mean`
3. 累加：`y_future = y_last_real + cumsum(Δy_real)`

`Y_last_abs` 在训练时就是 `data_Y_absolute[i + input_len - 1]`（标准化前的原始值），Step 5 用它作为还原起点。

表格





| 格式              | 压缩率             | 读取速度                    | 跨语言                | 支持多数组                                        | 适用场景                                            |

**为什么选择 NPZ？**

1. **多数组打包**：一个文件里同时存 `X`、`Y_diff`、`Y_last_abs`，比存三个 NPY 文件更整洁。
2. **压缩**：`savez_compressed` 用 zip 算法压缩，30 分钟窗口的浮点数组压缩率通常 >70%。
3. **零依赖**：NumPy 是 Python 科学计算的基石，无需安装 TensorFlow/PyTorch/HDF5 等重型库。
4. **读取速度**：`np.load()` 直接映射到内存，比 CSV 快 100 倍以上。

## 六、技术验证建议

1. **去掉 diff 试试**：把 `create_diff_sliding_windows` 里的差分逻辑注释掉，直接预测绝对温度，观察 Step 5 的训练 Loss 和收敛速度差异。
2. **换标准化方法**：把 Z-score 改成 `MinMaxScaler`（`(x - min) / (max - min)`），观察对训练稳定性的影响。
3. **加 EMA 特征**：在 `add_momentum_features` 里增加 `df[f"{feat}_ema5"] = df[feat].ewm(span=5).mean()`，观察 Step 3 入选特征的变化。
4. **调窗口大小**：把 `INPUT_LEN` 从 30 改成 60 或 10，观察模型对长/短期记忆的依赖程度。
5. **可视化一个样本**：打印 `X_train[0]` 和 `Y_train_diff[0]`，理解"输入 30 分钟多变量序列 → 输出 30 分钟温度变化量"的具体数值形态。
