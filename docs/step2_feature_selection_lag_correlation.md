# 滞后相关性分析——找到温度的"领先预告牌"

## 一、这个文件是做什么的？

Step 1 给了你一张"大宽表"：每一行是 1 分钟，每一列是一个传感器。现在问题来了——**这 13 个传感器，谁对"碳化取出液温度"真正有用？**

更关键的是：**谁能在温度变化之前，就提前发出信号？**

如果"反应段中部温度"比"取出液温度"早 5 分钟开始波动，那它就是**领先指标**（Leading Indicator），可以用来**预测未来**。反之，如果某个变量总是等温度变了它才变，那就是**滞后指标**，对预测毫无价值。

**这个脚本的目标就是：**

1. 对 13 个候选特征，逐个做"时间平移实验"
2. 计算每个特征在"提前 N 分钟"、"同步"、"滞后 N 分钟"时与目标的相关性
3. 筛选出**强相关 + 非滞后**的特征，保存成配置文件供 Step 4 使用

## 二、整体流程图（文字版）

```plain
读取 merged_wide_table.parquet（13列特征 + 1列目标）
    ↓
对每个特征：
    把它的时间轴往前/后平移 -30~+30 分钟
    计算平移后与目标温度的皮尔逊相关系数
    找出"相关性最强"的那个平移分钟数
    ↓
分类标记：
    Lag > 0 → 领先指标（能预测未来）
    Lag = 0 → 同步指标（同时变化）
    Lag < 0 → 滞后指标（滞后关系，不纳入预测特征）
    ↓
过滤：
    删掉滞后指标
    删掉相关系数 < 0.35 的弱相关特征
    ↓
可视化散点图 + 保存 feature_config.json
```

## 三、代码分段拆解 + 技术扩展

### 3.1 配置区：定义"时间望远镜"的焦距

```python
MAX_LAG = 30          # 最大考察滞后阶数（往前看30分钟）
CORR_THRESHOLD = 0.35  # 相关系数绝对值阈值
```

**知识点：为什么是 30 分钟？为什么是 0.35？**

| 参数                    | 含义                           | 工业考量                                                     |
| :---------------------- | :----------------------------- | :----------------------------------------------------------- |
| `MAX_LAG = 30`          | 最多看 30 分钟前的信号         | 碳化塔是大惯性设备，物理传热、传质过程通常需要 10~30 分钟。如果 30 分钟内都找不到领先关系，说明该变量与目标没有因果链。 |
| `CORR_THRESHOLD = 0.35` | 相关系数绝对值 ≥ 0.35 才算有效 | 工业现场噪声大，0.35 属于"弱到中等相关"。低于此值，模型很难从噪声中稳定学习。 |

### 3.2 核心函数：`discover_lead_indicators`

这是整个 Step 2 的**算法心脏**，三行核心代码做了一件非常巧妙的事：

```python
corrs = [df[target_var].corr(df[feat].shift(lag)) for lag in range(-max_lag, max_lag + 1)]
best_idx = np.argmax(np.abs(corrs))
best_lag = list(range(-max_lag, max_lag + 1))[best_idx]
```

#### 3.2.1 `df[feat].shift(lag)` —— 时间平移

**是什么？** 把一列数据在时间轴上"整体搬家"：

- `shift(5)` → 整列往下挪 5 行（相当于该特征**提前 5 分钟**出现）
- `shift(-5)` → 整列往上挪 5 行（相当于该特征**滞后 5 分钟**出现）
- `shift(0)` → 不动，同步对比

**小白比喻：** 想象两列数据是两列火车。`shift(5)` 就是把 A 火车往前开 5 分钟，看看此时 A 和 B 的速度是否同步变化。如果 A 往前开 5 分钟后，两车速度最像，说明 **A 比 B 早 5 分钟提速**——A 是 B 的领先指标。

#### 技术扩展：时间对齐还有哪些方法？

| 技术                        | 原理                 | 特点                                     | 适用场景                                                     |
| :-------------------------- | :------------------- | :--------------------------------------- | :----------------------------------------------------------- |
| **`shift(lag)`**            | 整列固定平移         |  极简、O(n) 速度、适合规则时间序列      | **本方案选择**：数据已重采样到 1 分钟固定间隔，shift 最简洁 |
| `merge_asof`                | 最近邻时间匹配       | 处理不规则时间戳（如传感器上报间隔抖动） | 事件驱动型数据、日志时间戳不整齐                             |
| 手动切片 `df.iloc[i:i+win]` | 滑窗截取后对齐       | 灵活，可处理变长滞后                     | 需要精细控制对齐边界时                                       |
| DTW（动态时间规整）         | 非线性时间轴扭曲匹配 | 能找"波形相似但节奏不同"的关系           | 语音、手势识别；工业上适合批次工艺曲线比对                   |

**为什么选择 `shift`？** 本项目的传感器数据已经通过 Step1 重采样到**严格 1 分钟对齐**的规整时间序列。在这种"铁轨已经铺好"的情况下，`shift` 就像火车时刻表调整，一行代码搞定，无需考虑时间戳抖动、缺失值插值等复杂问题。

------

#### 3.2.2 `df[target].corr(...)` —— 皮尔逊相关系数

**是什么？** 衡量两个变量**线性相关程度**的指标，范围 `[-1, 1]`：

- `1`：完美正相关（A 涨 B 一定涨）
- `-1`：完美负相关（A 涨 B 一定跌）
- `0`：无线性相关（但可能有非线性关系）

#### 技术扩展：相关性度量家族

| 方法                              | 衡量关系                 | 对异常值敏感度         | 计算速度                      | 适用场景                                                     |
| :-------------------------------- | :----------------------- | :--------------------- | :---------------------------- | :----------------------------------------------------------- |
| **皮尔逊 Pearson**                | 线性关系                 |  高（受极端值影响大） |  极快 O(n)                   | **本方案选择**：工业传感器在稳态工况下近似线性，且数据量大（万级~百万级），Pearson 计算最快 |
| 斯皮尔曼 Spearman                 | 单调关系（不限线性）     |  低（基于秩次）       |  较快 O(n log n)             | 存在明显异常值、或关系呈单调曲线（如阀门开度-流量）          |
| 肯德尔 Kendall                    | 单调关系                 |  极低（小样本更稳）   |  慢 O(n²)                    | 样本量极小（<<100）的实验室数据                              |
| 互信息 Mutual Information         | 任意统计依赖（含非线性） |  中等                 |  很慢（需分箱/估计概率密度） | 探索性分析、非线性主导的系统（如化工反应器非线性段）         |
| 距离相关系数 Distance Correlation | 任意依赖                 |  中等                 |  极慢                        | 学术研究、高维非线性因果关系发现                             |

**为什么选择皮尔逊？**

1. **速度优先**：本项目有 13 个特征 × 61 个 lag 点 = 793 次相关计算，Pearson 是 O(n) 的向量点积运算，毫秒级完成。
2. **物理直觉**：工业温度、压力、流量在**小范围波动**内（稳态附近）通常近似线性关系。皮尔逊的"线性假设"在这里不是负担，反而是**可解释性的优势**——工艺人员能理解"相关系数 0.8 就是强相关"。
3. **后续模型匹配**：我们最终用 LSTM 学习，LSTM 的神经元本质上是线性变换 + 非线性激活的组合。输入特征与目标有较强线性关系，能为神经网络提供**良好的梯度信号**。

> **注意**：如果后续发现模型在某些非线性工况（如开停车、大幅负荷调整）表现差，可以回来把 Pearson 换成 Spearman 或加入互信息做补充筛选。

------

#### 3.2.3 `np.argmax(np.abs(corrs))` —— 找最强相关的平移点

```python
best_idx = np.argmax(np.abs(corrs))
best_lag = list(range(-max_lag, max_lag + 1))[best_idx]
```

**是什么？** `corrs` 是一个长度为 61 的列表（-30 到 +30），存着每个 lag 下的相关系数。`np.argmax` 找到**绝对值最大**的那个位置，对应的就是"该特征与目标最默契的时间差"。

**为什么用 `abs`（绝对值）？** 因为负相关也是信息！比如"冷却水温度"升高 → "取出液温度"降低，这是强负相关，同样具有预测价值。只看正相关会漏掉这类关键特征。

valid_df = result_df[

#### 技术扩展：特征筛选方法全景图

| 方法                 | 原理                               | 自动化程度 | 可解释性     | 计算成本               | 适用场景                                                     |
| :------------------- | :--------------------------------- | :--------- | :----------- | :--------------------- | :----------------------------------------------------------- |
| **阈值法（本方案）** | 人工设定 corr > 0.35               |  半自动   |  极高     |  零成本               | **本方案选择**：工业落地需要"白盒"逻辑，工艺人员能看懂为什么选这个特征 |
| 递归特征消除 RFE     | 迭代训练模型，每次剔除最弱特征     |  全自动   |  中等      |  高（需训练多次模型） | 特征数极多（>100）、且模型训练很快时                         |
| L1 正则化（Lasso）   | 惩罚大系数，自动把弱特征系数压到 0 |  全自动   |  中等      |  中                   | 线性模型、需要自动稀疏化；但可能误删共线的重要特征           |
| 树模型重要性         | 计算特征在决策树中的分裂增益       |  全自动   |  中等      |  中                   | 非线性关系主导、特征与目标关系复杂；但偏向高基数特征         |
| 包装法 Wrapper       | 用最终模型性能反向选择特征子集     |  全自动   |  低（黑盒） |  极高                 | 竞赛场景、不计成本追求最高精度                               |

**为什么选择阈值法？** 工业场景不是 Kaggle 竞赛，**可解释性比极致精度更重要**。当工艺主任问"为什么选 CO2 进气压力作为输入"时，你可以指着散点图说："因为它提前 8 分钟与取出液温度有 0.72 的相关系数，超过 0.35 的门槛。" 这种解释在工厂里比"树模型重要性第 3 名"更有说服力。

**这张图的信息密度：**

## 五、常见坑点与自查清单

| 坑点             | 现象                                                         | 排查方法                                                     |
| :--------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| `shift` 方向搞反 | 把滞后指标误判为领先指标                                     | 打印 `best_lag` 为负数时，检查 `shift` 参数是否应为 `-lag`   |
| 绝对值 vs 原始值 | 强负相关（-0.8）被当成弱相关扔掉                             | 确认用了 `np.abs(corrs)` 取绝对值后再 `argmax`               |
| 阈值太高         | 筛选后只剩 1~2 个特征，模型欠拟合                            | 尝试降到 0.2，观察模型性能变化                               |
| 阈值太低         | 噪音特征混入，模型过拟合                                     | 尝试升到 0.5，观察验证集 Loss                                |
| 未剔除滞后指标   | Step 3 用未来信息预测现在，导致"数据泄露"（Leakage），模型在真实环境失效 | 严格检查 `valid_df` 中是否有 `best_lag < 0` 的行             |
| 散点图中文乱码   | 特征名显示为方块                                             | 确认 `plt.rcParams['font.sans-serif']` 包含系统存在的中文字体 |

## 六、技术验证建议

1. **相关性阈值敏感性分析**：建议将 `CORR_THRESHOLD` 分别设置为 0.5 和 0.2，对比入选特征数量、领先特征占比以及后续验证集指标的变化，用于评估筛选阈值对模型输入稳定性的影响。
2. **相关性度量方法对比**：可将 `df[target].corr(df[feat].shift(lag))` 替换为 `df[target].corr(df[feat].shift(lag), method='spearman')`，比较 Pearson 与 Spearman 在非线性或单调关系场景下的特征排序差异。
3. **滞后窗口范围评估**：建议将 `MAX_LAG` 扩展至 60 分钟，检查是否存在更长时间尺度的领先关系。若出现稳定的长滞后特征，需要结合工艺机理判断其是否对应慢响应回路或间接控制链路。
4. **配置扰动验证**：可在 `feature_config.json` 中调整单个特征的 `lag` 值，并在后续数据集构造和模型训练阶段观察性能变化，以评估时间平移配置对最终预测结果的敏感性。

**后续流程衔接**：Step 3 将读取 `feature_config.json`，依据各特征的 `lag` 配置完成时间平移对齐，并进一步构造差分预测数据集。该阶段会引入 `diff()`、滑动窗口切片（Sliding Window）、标准化（Normalization）和差分标签构造等关键步骤，其核心目标是将预测任务从绝对温度预测转换为温度变化量预测。
