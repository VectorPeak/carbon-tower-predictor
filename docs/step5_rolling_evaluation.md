# 差分还原评估 + DCS 实时滚动模拟

## 0x01. 这个文件是做什么的？

Step 4 训练好的模型输出的是**标准化后的温度差分**（每分钟变化多少）。但 DCS 操作工屏幕上显示的是**绝对温度**（°C）。这个脚本负责：

1. **加载模型权重**，在 Demo 数据上做推理
2. **把差分还原成绝对温度**（反标准化 + 累加）
3. **模块 A**：模拟"上线模式"——每 10 分钟刷新一次，只看前 10 分钟预测 vs 真实值，算 MAE
4. **模块 B**：长程发散分析——单次预测未来 30 分钟，拆解"近准远偏"的规律
5. **模块 C**：DCS 模拟——把离散预测拼接成连续轨迹，让操作工直观看到"红色预测线"与"蓝色真实线"的贴合度

## 0x03. 核心函数：`diff_to_absolute` —— 把"变化量"翻译回"温度值"



```python
def diff_to_absolute(y_last_abs_norm, y_diff_norm, target_mean, target_std):
    y_last_abs_real = y_last_abs_norm * target_std + target_mean
    y_diff_real = y_diff_norm * target_std
    cum_diff = np.cumsum(y_diff_real, axis=-1)
    y_abs_real = y_last_abs_real + cum_diff
    return y_abs_real
```

**四步还原公式：**






| 步骤 | 代码                        | 数学公式                                   | 物理含义                                         |
| :--- | :-------------------------- | :----------------------------------------- | :----------------------------------------------- |
| 1    | `y_last_abs_real = ...`     | `T_0 = T_{0,norm} \times \sigma + \mu`     | 把标准化后的"最后一个已知温度"还原成真实 °C      |
| 2    | `y_diff_real = ...`         | `\Delta_t = \Delta_{t,norm} \times \sigma` | 把标准化后的"每分钟变化量"还原成真实温差         |
| 3    | `cum_diff = np.cumsum(...)` | `\sum_{i=1}^{t} \Delta_i`                  | **累加**：第 1 分钟变多少，第 2 分钟累计变多少…… |
| 4    | `y_abs_real = ...`          | `T_t = T_0 + \sum \Delta_i`                | 从锚点出发，一步一步"走"到未来温度               |

**为什么差分预测必须这样还原？** 因为模型学的是**"从当前温度出发，每分钟该怎么变"**。它不负责记住"当前温度到底是 40°C 还是 24°C"——那个锚点（`y_last_abs`）是在 Step 3 就存好的真实值。模型只负责画"路线图"（差分），还原时把路线图"贴"到正确的起点上。

>  **常见错误**：有人还原时把 `target_mean` 也加到差分上（`Δ_real = Δ_norm × σ + μ`）。这是错的！差分的均值本来就接近 0，再加 μ 会导致温度漂移。

## 0x04. 模块拆解

### 4.1 模块 A：滚动评估（上线模式）



```python
for i in range(0, len(X_demo), 1):
    pred_diff_norm = model(X_demo[i:i+1]).cpu().numpy()[0]
    pred_abs_sequence = diff_to_absolute(Y_demo_last_abs_norm[i], pred_diff_norm, ...)
    rolling_preds_abs.extend(pred_abs_sequence[:ROLL_STRIDE])
```

**是什么？** 模拟模型**真正上线后的工作方式**：每 10 分钟（`ROLL_STRIDE`）推理一次，只看预测结果的前 10 分钟，与真实值对比。

**为什么 `stride=1`（`range(0, len(X_demo), 1)`）？** 这是**评估需要**，不是上线需要。为了算出最密集的 MAE，我们让窗口以 Step 3 的最小步长（5 分钟）逐个推进，每步都取前 10 分钟预测参与统计。这样得到的 MAE 是"理论最优密度"的评估，比真正上线时更严格。

**输出的 MAE 怎么解读？**

- `MAE = 0.16°C`：上线后，操作工看到的"过去 10 分钟预测曲线"与真实温度的平均偏差约 **0.16°C**
- 对于碳化塔（正常波动范围 ±2°C），0.16°C 意味着预测线几乎与真实线重合

### 4.2 模块 B：长程发散分析



```python
sample_indices = [k_start, k_start + 2, k_start + 4, k_start + 6]
for i in sample_indices:
    pred_abs_30min = diff_to_absolute(...)
    mae_0_5 = np.mean(np.abs(pred_abs_30min[0:5] - true_abs_30min[0:5]))
    mae_5_10 = ...
    mae_15_30 = ...
```

**是什么？** 单次预测未来 30 分钟，按时间段拆解误差：

- **0-5 分钟**：高置信区（MAE ~0.04°C）
- **5-10 分钟**：过渡区（MAE ~0.08°C）
- **15-30 分钟**：发散区（MAE ~0.27°C）

**为什么误差会随时间放大？** 这是**差分预测的固有特性**。模型预测的是"每分钟变化量"，还原时要 `cumsum`（累加）。如果第 1 分钟预测偏差 +0.1°C，第 2 分钟又偏差 +0.1°C……到第 30 分钟，累计偏差可能达到 +3°C。**误差像滚雪球一样越滚越大**。

**工业意义：** 这个结果直接回答工艺主任的灵魂拷问——"你说能预测 30 分钟，到底前几分钟能信？"

- 前 10 分钟：可以**直接用于闭环控制**（如自动调节阀门）
- 10-15 分钟：可以**用于预警**（"注意，温度可能偏离"）
- 15-30 分钟：只能**用于趋势参考**（"大趋势是升温还是降温"）

#### 技术扩展：时序预测评估指标家族






| 指标              | 公式                         | 对异常值敏感度   | 物理意义                   | 适用场景                                             |                 |                                                         |
| :---------------- | :--------------------------- | :--------------- | :------------------------- | :--------------------------------------------------- | --------------- | ------------------------------------------------------- |
| **MAE（本方案）** | `mean(                       | pred - true      | )`                         |  低                                                 | 平均偏差多少 °C | **本方案选择**：工业现场最直观，"差 0.2°C"人人能懂    |
| RMSE              | `sqrt(mean((pred-true)^2))`  |  高（平方放大） | 惩罚大偏差，反映"最坏情况" | 需要严控极端偏差的场景（如安全联锁）                 |                 |                                                         |
| MAPE              | `mean(                       | pred-true        | /true)`                    |  极高（true 接近 0 时爆炸）                         | 百分比误差      | 温度范围变化大时（如 20°C~200°C），避免低温段被过度惩罚 |
| sMAPE             | `symmetric MAPE`             |  中等           | 对称百分比                 | 温度有正负双向波动时                                 |                 |                                                         |
| R²                | 决定系数                     |  中等           | 模型解释了百分之多少的方差 | 学术报告、与基准模型对比                             |                 |                                                         |
| 方向准确率        | `sign(Δpred) == sign(Δtrue)` |  低             | 涨跌方向对了百分之多少     | 交易决策、趋势预警（不关心具体数值，只关心涨还是跌） |                 |                                                         |

**为什么选 MAE 做主指标？** 工业现场不讲"决定系数"，讲"你到底差了几度"。MAE 的单位和原始数据一致（°C），且对偶尔的大偏差不极端敏感（不像 RMSE 那样平方放大），更符合操作工对"平均准度"的直觉。

### 4.3 模块 C：DCS 实时滚动模拟（轨迹拼接）

这是**最复杂、也最贴近工业现场**的模块。

#### 4.3.1 索引对齐：为什么 `k_step = ROLL_STRIDE // 5`？



```python
dataset_stride = 5  # Step 3 切分时的固定步长，不可改
k_step = ROLL_STRIDE // dataset_stride  # 10 // 5 = 2
```

**说明：** Step 3 构造数据集时，相邻窗口间隔为 5 分钟。因此，当滚动预测间隔设为 10 分钟时，需要跳过 2 个窗口（`10 ÷ 5 = 2`）；当 `ROLL_STRIDE` 设为 15 分钟时，则需要跳过 3 个窗口。

**如果忘了这步会怎样？**

- `k` 每次只 +1（5 分钟），但你只取前 10 分钟 → **相邻两次预测重叠 5 分钟**
- Matplotlib 画线时，重叠段的两个不同预测值会被连线 → **红色轨迹"回折"**

#### 4.3.2 轨迹拼接逻辑



```python
stitched_pred_time = []
stitched_pred_vals = []

for r in range(num_rolls):
    k = k_start + r * k_step
    pred_abs_30 = diff_to_absolute(...)
    
    # 只取前 ROLL_STRIDE 分钟，拼到总轨迹上
    seg_time = np.arange(current_idx, current_idx + ROLL_STRIDE)
    seg_vals = pred_abs_30[:ROLL_STRIDE]
    stitched_pred_time.extend(seg_time)
    stitched_pred_vals.extend(seg_vals)
```

**是什么？** 像铺铁轨一样，每次铺 10 分钟长的预测段，首尾相接，形成一条**与真实值时间轴完全对齐**的连续预测线。

**可视化效果：**

- **蓝色实线**：真实发生的历史 + 未来温度
- **红色实线（拼接轨迹）**：每 10 分钟更新一次，与蓝色线并行延伸，操作工可直接对比贴合度
- **红色虚线（远景）**：最新一次完整 30 分钟预测，表示"当前系统看到的未来趋势"

#### 技术扩展：工业可视化策略家族






| 策略                   | 展示方式                       | 信息密度 | 操作工理解难度   | 适用场景                                             |
| :--------------------- | :----------------------------- | :------- | :--------------- | :--------------------------------------------------- |
| **轨迹拼接（本方案）** | 连续预测线与真实线并行         |  高   |  极易懂         | **本方案选择**：DCS 组态画面嵌入，最符合操作工习惯 |
| 离散预测条带           | 每 10 分钟画一条 30 分钟预测线 |  极高 |  难（满屏线） | 学术分析、模型调试阶段                               |
| 预测区间带             | 用阴影表示 [P10, P90] 置信区间 |  中    |  中等          | 需要表达不确定性的场景（如安全预警）                 |
| 数字仪表盘             | 只显示"当前预测值"一个数字     |  低     |  极易懂         | 辅助画面、非核心监控点                               |
| 热力图                 | 时间 × 预测步长的误差矩阵      |  极高 |  难           | 模型内部诊断、论文插图                               |

## 0x05. 关键代码行详解

### 5.1 `with torch.no_grad():` —— 推理时必须关梯度



```python
with torch.no_grad():
    pred_diff_norm = model(x_input).cpu().numpy()[0]
```

**是什么？** 在评估/推理阶段，告诉 PyTorch："我不需要算梯度，别浪费内存和算力。"

**为什么必须写？**

- 训练时需要梯度（`loss.backward()`），所以开梯度追踪
- 推理时如果开梯度，PyTorch 会记录整个计算图，占用大量显存，且推理速度变慢
- `torch.no_grad()` 是一个**上下文管理器**，包裹的代码块内所有张量操作都不追踪梯度

### 5.2 `model.eval()` —— 关掉 Dropout



```python
model.eval()
```

**是什么？** 把模型切换到"评估模式"。

**具体影响：**

- **Dropout 层**：训练时随机关 20% 神经元；评估时全部打开（否则同一输入每次推理结果不同！）
- **BatchNorm 层**：训练时用当前批的均值/方差；评估时用训练时累积的全局均值/方差

**忘记写的后果：** 每次运行 Step 5，预测结果都不一样（因为 Dropout 随机关神经元），MAE 忽高忽低，调试时让人崩溃。
